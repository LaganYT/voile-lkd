# Voile Linux engine, v1 (2026-10-03)

Rocket League runs on macOS arm64 with the real Easy Anti-Cheat active, through Linux: no virtual machine, no
Hypervisor.framework, no Rosetta. This document records the v1 state: architecture, what works with the
measurements behind it, how a session is assembled, and the known limits. The research behind each step is in
`journal/` (French; `01-integration-status.md` is the chronological log).

## Architecture

```
 macOS arm64 ──────────────────────────────────────────────────────────────────────────────────────────────
 │
 │  fexdarwin-run (one host process per guest process, real fork)          wsd (window server, native)
 │  ┌──────────────────────────────────────────────┐                       ┌──────────────────────────────┐
 │  │ guest x86-64 Linux userland                   │   UNIX socket +      │ Cocoa windows, input events   │
 │  │   Debian root (glibc 2.41, read-only)         │   SCM_RIGHTS (shm)   │ Metal presentation, overlay   │
 │  │   voile-wine built for Linux x86-64           │ ◄──────────────────► │ CoreAudio output (one         │
 │  │     winesailover.drv  (display, input)        │                      │   AudioUnit per stream)       │
 │  │     winesailaudio.drv (WASAPI → shared ring)  │                      └──────────────────────────────┘
 │  │     nptunix + Neptune d3d11/dxgi/d3d12 (PE)   │   vtest socket       ┌──────────────────────────────┐
 │  │   RocketLeague.exe + EAC Linux module         │ ◄──────────────────► │ virgl render server (Neptune) │
 │  ├──────────────────────────────────────────────┤   (shared blobs)     │   → DXMT → Metal              │
 │  │ FEXCore JIT: x86-64 → arm64 (Zagrios/FEX)     │                      └──────────────────────────────┘
 │  ├──────────────────────────────────────────────┤
 │  │ LKD: Linux system calls on Darwin             │
 │  │   mm (127.5 TiB guest window, 4 KiB pages on  │
 │  │   16 KiB host pages, SMC watch), fs, procfs,  │
 │  │   task (fork/exec/clone), sig, futex, net,    │
 │  │   ptrace (real stops for the anti-cheat)      │
 │  └──────────────────────────────────────────────┘
 ──────────────────────────────────────────────────────────────────────────────────────────────────────────
```

Guest memory: host address = `GuestBase` + guest address. The window goes from an adaptive base (above the
highest occupied host region) to 0x7ffffe000000, about 127.5 TiB, reserved as one kernel entry (`mach_vm_map`
with maximum protection NONE).

## What works (measured)

Evidence stamps refer to the run folders of the development workspace (`evidence/eac-runs/<stamp>`).

- **Easy Anti-Cheat**: the bootstrapper picks `linux64`, downloads and maps the module, "Launcher finished with:
  301, 'Easy Anti-Cheat successfully loaded in-game'" (first on 2026-10-02 22:12, `20261002T221224`; every later
  authenticated run). No integrity violation reported by the game's EAC callback.
- **Authentication**: Epic session, exchange code, Psyonix login ("Login successful"), online services, matchmaking.
- **Rendering**: main menu at 60 fps (about 16.1 ms per frame), Free Play (3D) at 61 fps after the deferred
  vertex/index buffer sync (`20261003T013654`). Text complete after the staging-map fix (`20261003T025436`).
- **Input**: keyboard (window can become key, `20261003T103502`), mouse, relative mouse while playing, released on
  focus loss. Input to screen latency 67–111 ms at the menu with `NPT_PRESENT_QUEUE=1` and `NPT_WSD_PACING=after`.
- **Audio**: WASAPI shared and event-driven streams through `winesailaudio.drv` and wsd/CoreAudio; the game opens
  float 48 kHz stereo (`20261003T103502`); test tone position 2.000 s after 2.154 s.
- **Clean exit** through the game's menus (rc 0, "Exit: Exiting.", no guest process left), several times.
- **Online match**: matchmaking reserved a server and the client loaded the arena, but see the limits.

Test programs: the freestanding x86-64 witnesses (w01–w21) and the glibc witnesses passed on LKD in their last runs (mutex under signal storm,
code and data in one host page, timed waits); 4,338 of 4,376 checks of the EAC probe campaign pass (the rest are
the old 2^46 window limit and one doubtful expected value).

## How a session is assembled (tools/dev/eac-run.py)

1. Check the game's binaries (sha256 before and after: the install is only read; the guest runs an APFS clone).
2. Build the Epic launch plan (SailOver's epic-kit); arguments are redacted from every log.
3. Start wsd (`--dir <socket dir>`, mode 0700) and the render server (`virgl_test_server --no-virgl`, socket in the
   same folder) under `run-with-timeout.sh`.
4. Put Neptune's d3d11/dxgi/d3d12 into the prefix (`WINEDLLOVERRIDES=d3d11,dxgi,d3d12=n`).
5. Run `fexdarwin-run` with `FEXDARWIN_LKD=1`, the read-only Debian root, binds `/opt/wine`, `/home/user`,
   `/games/rl`, `/run/sailover`, and `/bin/sh -c 'wine RocketLeague_EAC.exe …; wineserver -w'` (the registry is only
   written when wineserver exits).

## Safety rules (the Mac panicked twice before them)

- Reserve the guest window as one kernel entry. A plain `mmap(PROT_NONE)` of 2^46 bytes made 524,288 VM map
  entries per process (128 MiB chunks), and leaked processes exhausted the kernel zone.
- Every guest process follows a supervisor (`FEXDARWIN_SUPERVISOR_PID`) and ends within 0.5 s once it is gone.
- A process with more than 200,000 VM regions ends itself; at most 96 live guest processes per family.
- Builds: at most 4 jobs, `nice 10`.

## Debugging

- `FEXDARWIN_DUMP_DIR=<dir>`, then `touch <dir>/dump-request`: every guest process writes, per thread, the
  system call it is in with its arguments, the futex word and glibc mutex owner, and the stack words that point into
  executable mappings (module and offset). Read-only for the guest; it found the v1 deadlock below in one run.
- `FEXDARWIN_REGION_LOG`, `FEXDARWIN_TRACE`, `LKD_TRACE`; Neptune `NPT_TRACE_STAGING`, `NPT_TRACE_TEXUPD`,
  `NPT_TRACE_UNMAP`; wsd `WSD_LATENCY_PROBE`, `WSD_DEBUG_INPUT` with `wsdctl` (key, click, move).

Notable v1 fixes: the SMC write-fault retry bound in `lkd/src/mm/watch.c` (it refused legitimate stores, Wine
aborted a unix call holding a mutex and presents deadlocked); the D3D11 `MAP_WRITE` contents in the render server
(text vanished); borderless windows that could not become key (no keyboard).

## Known limits of v1

- **Online matches drop at load**: loading the arena takes about 26 s (about 3–5 s natively) and the game thread
  does not tick the network meanwhile; the server closes the connection when loading ends ("Error: 42",
  `20261003T103502`). Next work: profile the map load (JIT translation, file I/O through LKD, texture uploads).
- Code and frequently written data in one 16 KiB host page (for example a `.plt` next to `.data`) cause storms of
  SMC invalidations: correct now, but slow.
- DXMT is a borrowed binary; building it needs Xcode's Metal toolchain.
- Audio: no per-stream volume (only mute), no capture (microphone). No gamepad yet.
- Input latency 67–111 ms at the menu; 3D frame pacing limited by the render server's copies.
- The window server owns the pointer globally in relative mode; validated only by the focus-loss logic.
- The development scripts and most tests expect the development workspace layout.
