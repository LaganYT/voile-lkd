# LKD, Linux kernel on Darwin

The Linux x86-64 system call layer for a CPU engine (FEXCore) hosted in a macOS arm64 process. The engine calls it on every guest `SYSCALL`. No virtual machine, no Hypervisor.framework: the reasons are in [00-architecture-decision.md](../docs/journal/00-architecture-decision.md) (option O3). The answers of `/proc`, ptrace and every system call come from the runtime's real state; a missing function answers `ENOSYS`, visibly.

## Layout

```text
CMakeLists.txt, build.sh, check.sh   build and tests (cmake, ninja)
include/lkd/                         public API (engine <-> kernel)
  lkd.h        init, main task, lkd_syscall, signals, fork, exec, ptrace, engine services
  abi_x64.h    Linux x86-64 ABI (LX_*, struct lx_*), with static_asserts on sizes and offsets
  xlate.h      Linux <-> Darwin translations (errno, flags, signals, sockets, stat)
  syscall_nr.h generated by tools/gen_syscall_table.py (Linux v6.12, sha256 inside)
src/include/                         internal contracts between modules (task, fd, mm, vfs, sig, futex, ptrace, net)
src/core/                            dispatch, tracing, user memory, blocking calls, fork/exec, weak fallbacks
src/<module>/                        mm, fs, procfs, task, sig, net, ptrace: one folder per module
tests/ltest.h, tests/support/        test framework and fake engine
tests/test_<module>_*.c              one executable per file
docs/CONVENTIONS.md, OWNERS.md       rules, and which module owns each system call
docs/status/<module>.md              status of each module, updated at each milestone
docs/requests/<module>-<n>.md        change requests for a shared file
tools/                               table generator, owner check, test runners
NOTICE                               Apache-2.0 attribution
```

## Working on a module

1. Read `OWNERS.md`, `include/lkd/lkd.h`, the module's header in `src/include/` and `docs/CONVENTIONS.md`.
2. Write only in `src/<module>/`, `tests/test_<module>_*.c`, `docs/status/<module>.md` and `docs/requests/<module>-*.md`.
3. Define `lkd_<module>_init()` (the strong version; the core has an empty weak one) and register the module's system calls there with `LKD_REGISTER(name)`. Define the symbols the module's header marks `OWNER: <module>`: the weak definitions in `src/core/stubs_*.c` give way to them.
4. Every behavior has a test, `tests/test_<module>_<subject>.c`, which cites the Linux behavior it models.
5. A change needed in a shared file goes in `docs/requests/<module>-<n>.md`; work around it locally meanwhile.
6. Run `./check.sh` after each milestone (it builds, runs every test, and prints one PASS or FAIL line per program), and update `docs/status/<module>.md`: what exists, what passes, what comes next, what is missing.

## Building and testing

```sh
./build.sh          # configures and builds into ./build (liblkd.a, tests)
./check.sh          # builds, then runs each tests/test_*.c under 120 s, with a final count
tools/runtest.sh 30 build/tests/test_core_usermem   # one program, with a time limit
python3 tools/owners_check.py --list-unowned         # checks OWNERS.md, lists system calls without an owner
LKD_TRACE=1 build/tests/<test>   # traces system calls; LKD_TRACE=2 adds the entry lines
```

You need Xcode's clang and the macOS SDK, cmake and ninja (`CMAKE=` and `NINJA=` pick other copies). LKD builds in Release; `BUILD_TYPE=Debug` builds it unoptimized. `LKD_TEST_TIMEOUT` changes the 120 s test limit.

## Using it in the engine

Link with `-Wl,-force_load,liblkd.a`. Call `lkd_init_config` (optional), `lkd_init(&ops)`, `lkd_task_create_main(&spec)` and `lkd_set_current(t)`, then `lkd_syscall` on every `SYSCALL`. The full contract is at the top of `include/lkd/lkd.h` and in `docs/CONVENTIONS.md` §5.
